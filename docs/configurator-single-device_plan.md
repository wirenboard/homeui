# Конфигуратор устройств: одна сущность «устройство приложений» — план

Сейчас страница показывает две разные сущности: «устройство WB» (карточка с галочками по
контролам одного MQTT-устройства) и «созданное устройство» (строки-каналы с произвольными
привязками). В конфиге сущность одна — плоский список устройств приложений с `module` и
сервисами; карточка WB является лишь группировкой при загрузке. Двойственность путает
(вкладки диалога добавления), не даёт добавить к устройству WB канал другого устройства и
стала источником большинства ошибок (потерянное устройство, парковка снятых каналов,
коллизии ключей). План сводит всё к одной сущности; устройство WB остаётся только способом
подобрать контролы.

## Сценарии

1. **Список устройств** содержит карточки одного вида: название, число каналов, пометки
   «новое» / «изменено». Разделов «Устройства WB» и «Созданные» больше нет.
2. **Диалог добавления без вкладок.** Слева — устройства контроллера: устройства со
   свободными контролами идут первыми, у устройства с привязанными контролами подсказка
   «уже используется: N». Справа — их контролы с галочками, типом и значением, снизу — блок
   «Не подходит для приложений». В подвале две кнопки: основная «Добавить устройство» и
   дополнительная «Создать пустое устройство» (открывает плитки типов, как нынешняя вкладка
   «Создать»); из плиток можно вернуться кнопкой «К устройствам контроллера».
3. **Добавление из устройства контроллера** создаёт одну карточку с названием по имени
   устройства (например «WB-MSW v.4 90») и по строке на каждый отмеченный контрол; тип,
   имя, единицы и заряд батареи подставляются как сейчас. Кнопка добавления недоступна, пока
   у отмеченного контрола неоднозначного класса не выбран тип, поэтому строк без типа не
   бывает. Карточка сразу выбрана. Связь с устройством контроллера дальше не хранится.
4. **Повторное добавление того же устройства контроллера** разрешено: контролы, уже
   привязанные где-либо, показаны отмеченными и недоступными с пометкой «уже используется»,
   свободные — как обычно. Результат — новая карточка; если название уже занято, к нему
   добавляется « 2», « 3» и так далее.
5. **Панель устройства** одна для всех карточек: название, переключатели Matter / Алиса,
   строки-каналы. У строки: тип со значком, имя в приложениях, группа, единицы для числовых
   типов, привязка каждой роли типа к контролу, удаление. Контрол привязки выбирается из
   списка контролов контроллера, сгруппированного по устройствам (как в сегодняшней панели
   созданного устройства); потерянный контрол показывается с пометкой и сохраняется как есть.
   Если основной контрол строки публикуется и подходит нескольким типам, у строки есть выбор
   типа: привязка переходит на основную роль нового типа, did и группа сохраняются, имя по
   умолчанию обновляется, единицы остаются только у числовых типов. У карточки без строк
   написано «нет каналов».
6. **Уникальность названий.** Название карточки сравнивается так же, как оно пишется в
   `module` (без пробелов по краям, с учётом регистра; пустое — как `own-<did>`). У
   одноимённых карточек ошибка в поле названия и пометка в списке, «Сохранить» и «Экспорт»
   недоступны, в шапке объяснено почему.
7. **«Добавить канал» в панели** открывает тот же диалог, что и добавление устройства, но
   отмеченные контролы становятся строками текущей карточки. Устройство контроллера, из
   которого карточка собиралась, подбирается автоматически, если у его контролов есть
   свободные. Кнопка «Создать пустое устройство» в этом режиме превращается в «Пустой канал»
   и добавляет строку выбранного типа без привязок.
8. **Загрузка конфига** группирует устройства по `module` без эвристики «все привязки из
   одного устройства». Конфиги, записанные нынешней версией, загружаются без потерь: записи
   с `module` = идентификатор устройства WB становятся карточкой с таким названием.
   Записи с разными настройками адаптеров внутри одного `module` по‑прежнему помечаются
   предупреждением.
9. **Уведомление о новых устройствах** считает устройство настроенным, если хотя бы один
   его контрол привязан в какой-нибудь карточке.
10. **Экспорт, импорт, сохранение, сброс, мобильный режим «список или панель»** работают
   как сейчас.

## Контракты

Формат YAML не меняется. `module` — название карточки; пустое название при сохранении
заменяется на `own-<did первой строки>`, как сейчас. Порядок сервисов в записи — порядок
ролей в описании типа (первая привязанная роль получает `sid: 1`); у записей старых конфигов
порядок при пересохранении может измениться — на адаптеры это не влияет.

Публичный API стора (`@/stores/configurator`), которым пользуется страница:

- `devices: Device[]` — единственный список карточек вместо `wbs` и `own`.
  `Device { id, name, matter, alice, rows: DeviceRow[] }`, `DeviceRow` без изменений.
- `addDevice(name, rows: NewDeviceRow[]) → Device` — новая карточка, выбирается сразу;
  строки получают did по `nextDid()` и пустую группу; занятое название получает суффикс.
- `addRows(device, rows: NewDeviceRow[])` — добавить строки в карточку; группа новой строки
  наследуется от последней заполненной, как сейчас в `addOwnRow`.
- `removeRow(device, did)`, `removeDevice(id)`, `setName(device, name)`,
  `setAdapters(target, {matter?, alice?})`, `bindRole(row, role, key)`,
  `select({ id } | null)`, `selected` — как нынешние для созданного устройства.
- `updateRow(row, patch)` — только имя, группа и единицы.
- `changeType(row, type, role, name)` — смена типа строки с переносом привязки на `role`.
- `nameConflicts: Set<string>` — id карточек с совпадающим названием; `save()` при
  конфликте не отправляет конфиг и завершается ошибкой.
- `usedKeys: Set<string>` — ключи `device/control` всех привязок; без ключей-владельцев
  карточек WB.
- Удаляются: `wbs`, `own`, `addWb`, `removeWb`, `removeOwn`, `toggleChannel`, `addOwn`,
  `addOwnRow`, `removeOwnRow`, `setOwnName`, `Selection.kind`, типы `WbDevice`, `OwnDevice`,
  парковка снятых каналов. В модели: `fromConfig` отдаёт `{ devices, raw, orig, mixed }`,
  `rowServices(row)` без параметра `ownKey`, `boundRole` больше не нужен.

Диалог добавления (`AddDialog`): свойства `isOpened`, `onClose`, `initialDeviceId`, и новые
`target?: Device` — карточка, в которую добавляются строки; без него создаётся новая карточка;
`onAdded?: (device) => void` — вызывается после создания карточки.

## Решения

- **Название карточки из устройства контроллера: имя устройства или идентификатор?**
  A) имя («WB-MSW v.4 90»); B) идентификатор (`wb-msw-v4_90`), как сейчас пишется в `module`.
  Рекомендация: A — название видят в приложениях и в списке, идентификатор остаётся в
  привязках. Запрет совпадения названия с идентификатором устройства контроллера снимается:
  он был нужен только эвристике группировки.
- **Куда попадают контролы при повторном добавлении устройства контроллера?** A) всегда в
  новую карточку; B) предлагать слить с карточкой, где уже есть контролы этого устройства.
  Рекомендация: A — объединение делается через «Добавить канал» из нужной карточки, лишнего
  диалога не нужно.
- **Пометка потерянного устройства в списке.** Сейчас у карточки WB есть пометка «не найдено»,
  если устройство не публикуется. A) пометка у карточки, если хотя бы одна привязка потеряна;
  B) только пометка у строки в панели. Рекомендация: A — иначе потерю видно только после
  открытия карточки.
- **Снятие галочки в диалоге для уже добавленного контрола** (сценарий 4). A) недоступная
  отмеченная галочка; B) контрол скрыт. Рекомендация: A — видно, что устройство уже частично
  настроено.

## План тестирования

Существующие тесты карточек WB описывают поведение, которого не будет, поэтому их нужно
переписать — на это требуется явное разрешение (правило «не редактировать существующие тесты
без согласования»).

- `model.test.ts`: заменить сценарии карточек WB (в том числе round-trip MDM3 с основным
  каналом) на сценарии группировки по `module`; оставить тесты `buildService`, единиц,
  `raw`/`orig`, импортных случаев.
- `configurator-store.test.ts`: тесты `load`/`save`/`importConfig`/`revert` остаются с
  поправкой на `devices`; тесты `toggleChannel`/`addWb` заменить на `addDevice`/`addRows`
  (did, наследование группы, выбор карточки) и `bindRole`.
- Новые: загрузка конфига нынешнего формата (`module` = идентификатор WB, несколько
  записей) даёт одну карточку с нужными строками и теми же did; повторное добавление
  устройства с тем же названием даёт карточку с суффиксом и не меняет первую (отбор занятых
  контролов в диалоге тестами не покрыт — тестов компонентов нет по договорённости);
  `usedKeys` считается только по привязкам; конфликт названий (набор конфликтов, `save()`
  без отправки); смена типа строки; записи без `module` или с пустым `module` — одна
  безымянная карточка, которая пишется как `own-<did>`; пометка `mixed` при импорте, после
  `revert` и после сохранения; единицы числового датчика в карточке.
- `utils.test.ts`: новый тест `hasLostBinding`; тесты `ui` и остальной набор — без
  изменений, должны проходить.
- Ручная проверка на 192.168.88.97: загрузка сохранённого конфига, добавление WB‑MSW,
  «Добавить канал» из другого устройства, сохранение и повторная загрузка, мобильный режим.
