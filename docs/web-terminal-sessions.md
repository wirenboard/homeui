# Веб-консоль

Веб-консоль предназначена для входа в контроллер из веб-интерфейса с использованием системной учётной записи.

Сервис со стороны контроллера спроектирован так, что команда в консоли не прерывается, когда рвётся связь с браузером. Вкладка возвращается в ту же сессию. Из консоли можно обновить или откатить пакеты самого веб-интерфейса. Для этого каждая сессия работает в отдельном процессе, а сервис `wb-terminal-server` (слушатель) только направляет к ним подключения или запускает новые сессии.

nginx проксирует websocket-запросы `/api/terminal` в unix-сокет слушателя.

Слушатель запускает каждую сессию через `systemd-run` как временный сервис `wb-terminal-session-<id>.service`. Процесс сессии открывает PTY, запускает в нём `/bin/login` и создаёт свой сокет для получения дескрипторов соединения в каталоге `/run/wb-terminal-server/`. В имени сокета записаны id сессии и pid её `login`. Слушатель передаёт дескриптор соединения через сокет сессии, механизмом `SCM_RIGHTS`. Весь дальнейший обмен с браузером ведёт процесс сессии. Сессия работает в своей cgroup, поэтому перезапуск или остановка слушателя её не затрагивает.

Процесс сессии загружает код при старте и не замечает, что dpkg заменил файлы. После обновления или отката пакета слушатель работает на новой версии, а открытые сессии — на прежней.

Чтобы разные версии понимали друг друга, их связывают формат имени сокета в каталоге и протокол обмена через этот сокет. В протоколе только две команды: передача дескриптора соединения и «завершись», которой слушатель вытесняет лишнюю сессию.

Id сессии генерирует слушатель и передаёт сессии в командной строке, сессия сообщает его своей вкладке. Вкладка хранит id в `sessionStorage` и передаёт его в заголовке `Sec-WebSocket-Protocol`. Id виден в имени юнита и в журнале. Это не утечка: подключиться по id можно только через nginx, то есть администратором веб-интерфейса, а он и так может выполнять команды от root.

Пока вкладка браузера подключена, сессия не ограничена по времени. После обрыва связи она ждёт вкладку час и завершается, а если в ней идёт установка пакетов — ждёт до конца установки. Если вкладка пропала молча (уснул ноутбук, пропала сеть), обрыв замечается, когда nginx закроет соединение, — не позже чем через час. Сессия завершается и тогда, когда заканчивается `login`: пользователь вышел из шелла или не ввёл пароль.

Одновременно работает не больше пяти сессий. Шестое подключение вытесняет самую старую сессию, кроме той, где идёт установка.

Сессию показывает только одна вкладка браузера. Если открыть её в другой вкладке, прежняя отключается и самостоятельно не переподключается.

## Диагностика

Сессии:

```bash
systemctl list-units 'wb-terminal-session-*'    # процессы сессий, по юниту на сессию
systemctl stop wb-terminal-session-<id>         # завершить сессию
ls -l /run/wb-terminal-server/                  # сокеты сессий: <id>.<pid login>.sock
who                                             # вошедшие: pts, время, адрес браузера
loginctl list-sessions                          # сессии logind (у них свой номер, не id консоли)
loginctl session-status <номер>                 # что запущено в сессии
loginctl terminate-session <номер>              # завершить сессию
```

Журналы:

```bash
journalctl -t wb-terminal-server                # слушатель и все сессии вместе
journalctl -u wb-terminal-server                # только слушатель, с ошибками запуска сессий
journalctl -u wb-terminal-session-<id>          # одна сессия
journalctl -t login                             # входы и неудачные попытки
```
